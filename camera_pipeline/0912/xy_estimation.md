# 距離2本から (X, Y) を出す方法と、その精度の非対称性

`homography.trilaterate()` が何をしているかと、**なぜ X は当たるのに Y だけ壊れるのか**。
2026-09-12 の実測でこの非対称性が表面化したので、設計の指針として残す。
実データでの現れ方は `README.md`、数値の再現は `check_markers.py`。

## 結論

| | X（線に沿った位置） | Y（線からの横ずれ） |
|---|---|---|
| 何から決まるか | 2本の距離の**差** | 2本の距離の**和**が基線を超える分（＝寄り道） |
| 測定誤差の伝わり方 | **1倍以下**（誤差は増幅されない） | **b/(4Y) 倍**（線に近いほど発散） |
| 実測での残差 | 0.040 m | 0.365 m（誤差エネルギーの99%） |
| 対策 | 不要 | 基線を短く・点を線から離す |

Y の精度は「丁寧に測ったか」ではなく**点をどこに置いたか**でほぼ決まる。
置き方を間違えると、どれだけ丁寧に測っても目標精度に届かない。

## 前提と導出

アンカー A=(0,0)、B=(b,0) を地上座標系の定義に使う。点 P=(X,Y) について、
現地で測れるのは A・B からの距離 `ra`, `rb` の2本だけ（方向は測れない）。

```
ra² = X² + Y²
rb² = (X−b)² + Y²
```

辺々を引くと Y² が消えて、X が線形に解ける：

```
ra² − rb² = 2bX − b²
→  X = (ra² − rb² + b²) / (2b)
→  Y = √(ra² − X²)
```

この**解く順序が非対称性の原因**。X は引き算で素直に出るが、Y は X を求めた後の
残り物（平方根の中身）として出てくる。

### 鏡映

√ は符号を選べないので、AB線の両側にある2点を区別できない。実装は Y≥0 の解を返し、
「全点を線の同じ側に置く」運用でこれを回避している（`trilaterate()` のdocstring）。

## 感度：X はなぜ安全か

```
∂X/∂ra = ra/b,   ∂X/∂rb = −rb/b
```

`ra`, `rb` は基線 b と同程度の大きさなので、係数は**おおむね1以下**。
メジャーが5cm狂っても X は最大5cm程度しか動かない。誤差は増幅されない。

実測13点での確認（±5cm を与えたときの X の振れ幅）：

```
P1 0.009 m   P5 0.041 m   P9  0.062 m   P13 0.094 m
```

全点で 10cm 未満。**X はメジャーの精度がそのまま出る。**

## 感度：Y はなぜ危ないか

```
∂Y/∂ra = ra(b−X) / (bY),   ∂Y/∂rb = X·rb / (bY)
```

分母に **Y** がある。線に近づく（Y→0）ほど係数が発散する。

直感的には「寄り道」で理解できる。A→P→B と回った距離が、まっすぐ A→B と
行く場合をどれだけ超えるか：

```
s = ra + rb − b
```

中央付近では `s ≈ 2Y²/b`。**Y に対して二次でしか増えない**ので、
線に近い点の s は極端に小さい（b=35.4 m のとき）：

| 実際の Y | 寄り道 s |
|---|---|
| 1 m | **5.6 cm** |
| 2 m | 22.5 cm |
| 3 m | 50.5 cm |
| 4 m | 89.3 cm |

35.4 m のロープを張って途中を横に1m引っ張っても、必要な長さは 5.6 cm しか増えない。
メジャーの読みが5cm刻みなら、**「1m引っ張った」と「引っ張っていない」が区別できない**。

これを逆に解くと、Y の不確かさは寄り道の不確かさ δ に対して

```
σY ≈ (b / 4Y) · δ
```

b=35.4 m, Y=2 m, δ=10 cm なら σY ≈ 0.44 m（数値計算では 0.457 m。よく一致する）。

### 2つの副作用

**1. ゼロで頭打ちになる（誤差が平均化されない）**

s は負になれない。誤差で負側に振れた分は 0 にクリップされるか、
`√` の中身が負になって「三角不等式を満たさない」として棄却される。
つまり誤差が対称に散らばらず、**常に線に寄せる方向に偏る**。

2026-09-12 の実測では、P4・P7 がぴったり `Y = 0.000000` になった。
これは「0 と測れた」のではなく**境界で頭打ちになった**結果で、
P8・P10 はさらに行き過ぎて棄却された（`ra+rb` が基線より 5〜10 cm 短い）。

**2. 最小二乗を汚す**

DLT は全点を等しく信頼して当てはめるので、Y が1m狂った点が1つ混じると H 全体が傾く。
X が正しくても救いにならない。実測では、退化した2点（P4・P7）を外すだけで
RMS 残差が 0.368 m → 0.229 m に改善した。**「無いより悪い」点が存在する。**

## 基線は長ければ良いわけではない

`trilaterate()` のdocstringは「アンカーはできるだけ離す（理想は10m以上）」としているが、
これは**基線の外側にある遠方の点**を三角測量する場合の話。

`σY ≈ (b/4Y)·δ` は **b に比例する**ので、**アンカー間にあって線に近い点**では逆になる。
中央・Y=2 m・読み取り±5cm での数値計算：

| 基線 b | σY |
|---|---|
| 10 m | 0.135 m |
| 20 m | 0.257 m |
| 35.4 m（2026-09-12） | 0.457 m |

2026-09-12 に基線を 20 m → 35.4 m に伸ばしたのは、この意味では**裏目**だった。

## 設計指針

`σY ≈ (b/4Y)·δ` を目標精度以下にすればよい。動かせるのは3つ。

1. **点を線から離す（Y を大きく）— 効果が最も大きい**
   b=35.4 m で 0.28 m を満たすには **Y ≥ 3.25 m** が必要。歩道幅4mだと
   実質的に遠い側の縁しか使えない。実際 2026-09-12 に生き残った4点
   （P3・P6・P9・P11）は Y=2.6〜3.8 m の列だった
2. **基線を詰める（b を小さく）**
   アンカー間の点しか測らないなら、基線は 15〜20 m で十分。
   ただし X の精度と、H を拘束する範囲の広さとのトレードオフになる
3. **読み取りを細かく（δ を小さく）— 効果は薄い**
   1 cm 単位で読んでも σY は 1/5 になるだけで、Y=1 m の点は依然として厳しい

**線に近い点をどうしても使いたい場合は、この測り方をやめる。**
AB に張った紐からの**垂線距離を直接測れば、それがそのまま Y** になり、
二次の潰れを経由しない（`σY = δ` になる）。

### 配置の型

- コーンは**遠い側の縁に1列**（Y ≈ 3.5 m）。アンカーの Y=0 と組み合わせれば、
  H の退化を防ぐ副軸方向の広がりは確保できる
- 線の近くには置かない。置くなら垂線距離で測る
- **頭上に街灯・樹冠がある場所を避ける**。見下ろす配置では真下が死角になり、
  2026-09-12 は P13 が街灯の傘に隠れて使えなかった

## 現地での検算

入力する前に、この2つだけ確認すれば退化した点を弾ける。

```
1) ra + rb > b          … 満たさないなら測定ミス（平面上に存在しない）
2) ra + rb − b > 0.2 m  … 下回るなら Y が誤差に埋もれる（置き直すか垂線距離で測る）
```

`pick_markers.py` は (1) を棄却し、(2) 相当として `Y < 0.10 m` で警告を出す。
ただし警告は端末に流れるだけなので、**現地では紙の上で (2) を先に計算しておくとよい**。
