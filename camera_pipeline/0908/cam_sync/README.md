# カメラ・レーダー同期の枚数検証（S1）

## 結果（2026-08-20）

**両方同時に回した2組とも、`.cam`のフレーム数と`.dat`のフレーム数が一致した（50枚/50フレーム）。**
index対応（1レーダーフレーム=1枚）の前提は、今回の机上テスト（10秒×2本）では崩れていない。

| ファイル | camフレーム数 | datフレーム数 | 判定 |
|---|---|---|---|
| `atlas_log_20260820_155904` | 50 | 50 | OK |
| `atlas_log_20260820_155929` | 50 | 50 | OK |

解像度は両方とも 3840×2160（`0817/camera_capture.md`の実測と同じ）。

### 意味

`0817/camera_capture.md`の「次にやること」にあった
「`.cam`→連番画像抽出スクリプト（`.dat`のフレーム数との一致チェック込み）」を実装し、
**両方同時に回すのは初めて**（`../../400MHz変更用/meeting/2026-09-08.md` S1）というテストを兼ねて検証した。
今回は10秒の短い録画なので同注意点3（長時間だとフレーム落ちの余地）は検証できていない。
本番の録画長（数十秒〜）で同じチェックをする必要がある。

## 使い方

`0817/capture/cam_extract.py`の`--dat`オプションが同じ突き合わせを行うため、
専用スクリプトは持たない（`cam_extract.py`の重複を解消・2026-08-20）。

```
python ../../0817/capture/cam_extract.py xxx.cam.gz --dat xxx.dat
```

`.cam`からJPEGフレームを連番で抽出しつつ、`.dat`のファイルサイズから計算したフレーム数と
枚数を比較する。抽出はJPEGのSOI(`FFD8FF`)〜EOI(`FFD9`)をスキャンする方式。

## スコープ判断（2026-08-20）

**長時間録画の活用は当面想定しないため、本番録画長での再検証はしない。**
今回の10秒×2本で同一フレームレート・枚数一致が確認できたことで、
現時点の用途（短時間シナリオの撮影）に対する検証としては十分と判断し、この項目はここで区切る。

フレーム落ちが起きた場合の検出（同期イベント＝金属板）は、
長時間録画を扱う想定が生じたときに改めて必要性を判断する。
