# パイプライン全体像・境界

## 目的

`../../400MHz変更用/` の検出器を学習させるための教師ラベル（地上座標 (X,Y) + クラス）を、
実測カメラ映像から生成する。レーダー実測（`.dat`）とは別系統で、映像だけで完結する部分をここで扱う。

## 前提: カメラ・レーダーの同期は取得の仕組みで担保されている

カメラ映像はレーダーセンサーのソフトウェア経由で取得しており、撮影の開始・終了はレーダー
（`.dat`）側と共有された制御下にある。**同期はこのパイプラインが作り出すものではなく、
取得の仕組み自体によって成立している前提**として扱う。

このパイプラインが行うのは、その前提が壊れていないかの検証のみ:

- `.dat` にタイムスタンプが無いため、運用面では同期イベント（金属板）も併用する
- 枚数照合（`.cam` のフレーム数 vs `.dat` のファイルサイズから算出したフレーム数）を
  `cam_extract.py --dat` で行う（`run_pipeline.py` に `.cam` を渡した場合も同じ照合が走る）。
  10秒×2本の短時間録画では一致を確認済み
  （詳細は `../0908/cam_sync/README.md`）
- 長時間録画での再検証は現時点では想定しておらず未実施

## 境界: ここで扱うこと／扱わないこと

| 扱う | 扱わない |
|---|---|
| 映像→YOLO検出→トラッキング | レーダー信号処理（FFT・RDマップ生成） |
| カメラ内部パラメータ較正・ホモグラフィ | 検出器モデル本体（RadarUNet3DSoftmax等） |
| 接地点の定義・地上座標(X,Y)への変換 | カメラ検出とレーダーピークの対応付け（S3、`0908/matching/`） |
| 同期前提の検証（枚数照合のみ。ヘッダの意味解釈はしない） | 教師テンソルの組み立て（S4） |

対応付け（S3）以降がレーダー側と混ざる処理のため、意図的にメイン側（`../../400MHz変更用/`）に残している。

## 処理フロー

```
映像 (.mp4 / .cam)
    │
    ▼ detect_yolo.py（ultralytics, YOLO+ByteTrack）
検出結果CSV（frame, track_id, cls, bbox, conf）
    │
    ▼ merge_cyclist()（detections.py）
    │   person+bicycle → cyclist（接地点=bicycleの下辺）
    │   対応なしperson → pedestrian
    │   vehicle系はそのまま
統合済み検出（+ 接地点 foot_u, foot_v）
    │
    ▼ to_ground()（homography.py の H を適用）
地上座標ラベル (X, Y) ＋ クラス  ← ラベルの正本
    │
    │  （学習データ組み立て時のみ）
    ▼ add_slant_range()
    + 斜距離 R_slant
    │
    ▼ 受け渡し
../../400MHz変更用/0908/matching/ （S3: レーダーピークとの対応付け）
```
