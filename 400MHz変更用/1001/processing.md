# 1001 の処理の流れ（.dat から結論の数字まで）

この文書だけで、10/1 のデータにどんな処理をかけて README・`report_1002.md` の数字と図を出したかが
追えるようにまとめたもの。結果と判断は `README.md`、報告の原稿は `report_1002.md` にある。

## 0. 全体像

```
.dat（生のIF信号）
  │ ① atlas_export.py           TX 分離 → MTI → 距離FFT → 速度FFT
  ▼
複素 RD テンソル .npz  (Frame, TX, RX, Doppler, Range)
  │ ② moving_power_db           8ch を振幅で加算 → dB → DC ビンを除外 → 速度方向に最大
  ▼
距離−時間の動体電力  (Frame, Range)  ……… 距離−時間図（range_time 系）はこれを描いたもの
  │ ③ build_ridges / pick_ridge  しきい値超えの極大をフレーム間で繋ぐ → 本物らしい1本を選ぶ
  ▼
軌跡 R(t)  （点の列: 時刻 t, 距離 R, ドップラー）
  │ ④ profile_d                  R(t)² = v²(t−t_min)² + d² を当てはめ、d を動かして残差を見る
  ▼
「d̂ が決まるか」の判定  ＋  ⑤ analyze_night の (A)(A')(B)(C)
```

コードの場所: ①② ③ は `../0727/`（`atlas_export.py`, `atlas_ridge_track.py`）、④⑤ は本フォルダ。

## 2. ① .dat → 複素 RD テンソル（`../0727/atlas_export.py`）

```bash
python ../0727/atlas_export.py data/raw/<file>.dat --outdir data/export            # MTI あり（既定）
python ../0727/atlas_export.py data/raw/<file>.dat --outdir data/export_nomti --no-mti
```

`rd_tensor()` が次の順で処理する。

1. **TX の分離。** 偶数チャープが TX0、奇数チャープが TX1。
   `(Frame, Chirp=32, Rx, Sample)` → `(Frame, TX=2, Rx=4, Chirp=16, Sample=256)`
2. **MTI（静止クラッタ抑制）。** 1フレームの中の 16 チャープについて、距離サンプル・アンテナごとに
   平均を取り、各チャープから引く（§7 で詳しく）
   ```python
   x = x - x.mean(axis=-2, keepdims=True)   # Chirp 方向の平均
   ```
3. **距離 FFT。** 距離方向に Hanning 窓 → 実数 FFT（256 点、ゼロ埋めなし）。1ビン ＝ 0.846 m
4. **速度 FFT。** チャープ方向に Hanning 窓 → FFT（16 点）→ 速度 0 が中央に来るよう並べ替え。1ビン ＝ 0.6 m/s
5. 保存。`rd`: `(Frame=150, TX=2, RX=4, Doppler=16, Range=129)` の complex64。
   軸は `range_m`, `vel_ms`, `t_rel_s`

位相を残した 8 チャンネル分の複素数で保存している（角度推定を後でできるように）。1001 の解析では角度は使っていない。

## 3. ② 距離−時間の動体電力（`../0727/atlas_ridge_track.py` の `moving_power_db`）

各フレーム・各距離ビンについて「動いているものの強さ」を 1 つの数にする。

```python
db  = 20*log10( Σ_{TX,RX} |rd| )          # (Frame, Doppler, Range) 8ch の振幅を足す（位相は揃えない）
mov = db から速度 0 のビン（DC）を除いたもの   # |v| ≥ 1 ビン（0.6 m/s）だけ残す
pw  = mov の速度方向の最大                   # (Frame, Range)  動体電力 [dB]
vel = そのとき最大だった速度ビンの値           # (Frame, Range)  ドップラー [m/s]
```

- **DC ビンを除くのは、MTI で静止物を引いた後も、窓関数の影響で DC ビンに消え残りが出るため**。
  したがって「速度 0 を捨てる」のは ① で平均を引いた**後**、この段階で行う
- `pw` をそのまま画像にしたのが距離−時間図（`figures/range_time.png`, `figures/night_range_time.png`）。
  横軸が距離、縦軸が時間、色が `pw`
- **雑音床。** 日中の解析（`analyze_1001.py`）では `pw` の絶対値 [dB] を使い、雑音床は 13.5 dB。
  夜の (A) では距離ビンごとに `pw` の時間方向の中央値を床とみなし、そこからの超過 [dB] を使う
  （目標は 30 s のうち数秒しかいないので、中央値はほぼ目標なしの値になる）

### MTI なし版の距離−時間図（`plot_range_time_nomti.py`）

`data/export_nomti/` から同じ量を作るが、DC ビンも含めて最大を取る。静止物が全距離で最大になるので
**目標は見えない**。静止クラッタが距離ごとにどれだけ居るかを見るための図（README §9）。

## 4. ③ 軌跡の抽出（`build_ridges` と `pick_ridge`）

### build_ridges：フレームをまたいで点を繋ぐ

1. 各フレームで、`pw` がしきい値 `thr` を超え、かつ隣の距離ビンより大きい点（極大）を候補にする
2. 前のフレームまでにできている軌跡（尾根）と候補を、次の条件で対応づける
   - **距離のゲート:** 1フレームで動ける距離は 最大速度 × 0.2 s ＝ 0.96 m → **2 ビン**以内。見失っている間はフレーム数倍に広げる
   - **ドップラーのゲート:** 直前の点とのドップラー差が **2 ビン（1.2 m/s）以内**
   - 複数の組があるときは、ドップラー差が小さい組から確定する（静止物の残差に目標を奪われないように）
3. **3 フレーム（0.6 s）までの見失い**は同じ尾根として繋ぐ。**5 点未満**の尾根は捨てる
4. 各尾根について、距離の時間変化の傾き `slope` [m/s] と、ドップラーの中央値 `vel` [m/s] を出す

### pick_ridge：本物の目標らしい1本を選ぶ

- `slope`（フレーム間の位置の変化）と `vel`（1フレーム内の位相の回転）は別々の物理量から出る。
  **両者の差が 1 m/s 未満**のものを実在の移動目標とみなす
- **|slope| > 0.3 m/s**（動いていない持続クラッタの帯を除く）
- 条件を満たす中で**点数が最も多い**ものを、その走行の軌跡とする

| | 距離の範囲 | しきい値 |
|---|---|---|
| 日中（`analyze_1001.py`） | 25〜55 m | 22 dB（`pw` の絶対値） |
| 夜（`analyze_night.py`） | 20〜60 m | 20 dB（同上） |

近距離 0〜8 m は窓枠・三脚・操作者、R ≈ 18, 34 m には全時刻に居座る静止物の残差の帯がある（README §2）。

## 5. ④ 軌跡モデルと d の当てはめ（`analyze_1001.py` の `profile_d`）

被験者は道路に沿ってまっすぐ等速 $v$ で動くとみなす。最接近の時刻を $t_\text{min}$、そのときの距離（横方向離隔）を $d$ とすると

$$R(t)^2 = v^2 (t - t_\text{min})^2 + d^2$$

- $d$ は最接近点付近の曲がり方にしか現れない。最接近点から離れると $R \approx v|t - t_\text{min}| + d^2/(2v|t-t_\text{min}|)$ で、ほぼ直線になる
- `profile_d` は $d$ を格子で固定し、$v$ を 0.5〜6 m/s で総当たり、$t_\text{min}$ はその $v$ での最適値を代入して、**残差 rms の最小**を記録する
- **判定:** $d$ を動かしても残差がほとんど変わらなければ、データから $d$ は決まらない。
  指標は「残差の最大 / 最小」。日中は 1.16、夜は中央値 1.03（31 本すべて 1.2 未満）

## 6. ⑤ 夜の解析（`analyze_night.py`）

```bash
cd 400MHz変更用/1001

python analyze_night.py          # 表を標準出力に、図3枚を figures/ に出す
python plot_range_time_nomti.py  # MTI なしの距離−時間図2枚
```

### 幾何（コーンの斜距離から）

- C1（手前・左の縁、23.28 m）と C5（奥・左の縁、49.41 m）、その間の地上距離 45.82 m の3つから、
  $R^2 = d^2 + (s - s_0)^2$ を連立して**垂線の足の位置 $s_0$ と $d$** を解く（`foot_of_perpendicular`）。
  結果は C1 から奥へ 2.2 m、左の縁で $d$ = 23.2 m
- 隣り合うレーンの $d$ の差（約 0.78 m）は、**道幅 4 m（未実測）**と3レーン等分を仮定して出している（`lane_delta_d`）

### (A) 距離帯ごとの目標強度 → `figures/night_intensity_vs_range.png`

- 各走行・各距離ビンで「床からの超過」の時間方向の最大を取る。被験者は毎回走路の全域を通るので、
  軌跡の抽出に頼らず「そこを通ったときの強さ」が取れる
- 36 本の中央値を、R 36〜45 m に合わせた $R^{-4}$ 則の期待と比べる。手前ほど期待より弱い（R 21〜24 m で 18.9 dB 不足）
- MTI あり（現行）と、MTI なし＋フレーム間差分の2通りで出す

### (A') 手前に目標が残っているか

- 抽出した軌跡から速度を出し、見えている手前端から C1 まで等速で外挿した経路を作る
- その経路の上の強度と、同じ経路を時間だけずらした対照（目標が居ない時刻）を比べる
- 差は現行 MTI で +0.1 dB、フレーム間差分で +0.7 dB。**処理を変えても手前の反射は戻らない**

### (B) d が決まるか → `figures/night_d_identifiability.png` の左

§5 の `profile_d` を、10 点以上の軌跡が取れた 31 本に掛ける。

### (C) どこまで見えれば d が決まるか → 同じ図の右

- 「見えている最小距離」より手前は観測できないとして、$\hat d$ の標準偏差の下限（Cramér–Rao 下限）を計算する（`crb_sigma_d`）
- 1フレームの距離誤差は 0.5 m と仮定（量子化 0.846/√12 ≈ 0.24 m に揺らぎを上乗せ）
- 隣接レーン差 0.78 m を下回るには、R ≈ 26 m より手前まで見えている必要がある

### 距離−時間図 → `figures/night_range_time.png`

代表 12 本の `pw`（§3）を並べたもの。上段が徒歩（No.1, 2, 7, 8, 13, 14）、下段が自転車（No.19, 20, 25, 26, 31, 32）。
各段は左からレーン1・2・3 の接近と離反。赤破線はコーンの斜距離。選んだ走行は `RANGE_TIME_PICK`。

## 7. MTI の注意点（速度が 0 に近い目標は削られる）

### やっていること

1フレーム（0.2 s）の中で、同じ TX のチャープを 650 µs おきに 16 回撃つ（計 10.4 ms）。
**その 16 回で変わらない成分（止まっている物の反射）を、平均を引くことで消す。**
平均はフレームごとに計算し直すので、シナリオごとに違う値を引いていても、かけている処理は
「径方向速度 0 を消すフィルタ」として同じである。

### 削られる範囲

径方向速度 0 の付近だけが削られる。N = 16 チャープの正弦波で、平均を引いたあとに残る電力の目安:

| 径方向速度 | 残る電力 |
|---|---|
| 0.6 m/s 以上（1 ビン以上） | ほぼ全部 |
| 約 0.3 m/s（半ビン） | 約 −2 dB |
| 約 0.15 m/s | 約 −7 dB |

さらに ② で DC ビンを除外するので、**|v_r| ≲ 0.3 m/s の目標は見えなくなる**。

### 徒歩と自転車で影響が違う

径方向速度は $v_r = v \cdot X/R$（$X$ は最接近点からの走路上の距離）なので、最接近点の前後で 0 に近づく。
実測の幾何（$d$ = 23.2 m）で $|v_r| < 0.3$ m/s になる区間は

- 徒歩（1.3 m/s）: 最接近点の前後 約 5.5 m、時間にして約 8 秒
- 自転車（2.5 m/s）: 前後 約 2.8 m、約 2 秒

**徒歩は、$d$ を決めるのに最も大事な区間を MTI で消される。**

10/1 夜のデータでは見えていたのが R ≥ 29 m だけなので、この影響はまだ出ていない
（軌跡上の点で 0.6 m/s の割合は徒歩 41%、自転車 25%。いずれも 1 ビン以上）。

### 方針

レーダーの向きを変えて最接近点付近が見えるようになったら、**最接近点付近の解析には MTI ではなく
フレーム間差分（MTI なしの RD の 0.2 s 前との差）を使う。** 0.2 s あれば径方向速度が小さくても
位相が回るので、目標が残る。`analyze_night.py` の `framediff_excess` がその実装。

## 9. 用語

| 用語 | 意味 |
|---|---|
| RD マップ | 距離 × 速度（ドップラー）の2次元の強度。1フレームに1枚 |
| MTI | Moving Target Indication。ここではチャープ間平均の減算による静止物の除去 |
| DC ビン | 速度 0 の速度ビン |
| 尾根 | 距離−時間図の上で、移動目標が作る斜めの筋。抽出した点の列 |
| 横方向離隔 $d$ | 最接近点でのレーダーからの距離。走行レーンによって変わる |
| 最接近点 | 走路上でレーダーに最も近い点（レーダーから走路への垂線の足）。そこで径方向速度は 0 |
| 床（雑音床） | 目標が居ないときの強度の水準 |
