## 学習実行時のトラブルと対処

### VRAM不足
- カーネル再起動なしで再実行すると PyTorch が reserved メモリを保持したまま（最大 8454 MB）
- 次の学習に残り 666 MB しか使えず詰まる
- 対処：**学習前に必ずカーネルを再起動する**

### DataLoader I/O ボトルネック
- `MultiTargetDataset.__getitem__` でバッチごとに `.npz` を2回 `np.load`（二重ロード）
- BATCH_SIZE=4、113 バッチ/epoch、SSD でも 1 エポック 10 分超
- 対処：`__init__` で全サンプルを RAM にプリロード、`__getitem__` はリストから返すだけに変更

### Conv3d 初回 CUDA カーネルコンパイル
- 初回実行時に cuDNN がレイヤーごとの最適アルゴリズムを選択・確定するため、最初のエポックだけ数分かかる
- 2エポック目以降は 10〜20 秒/epoch（BATCH_SIZE=8 on RTX 3060 Ti）

## 学習結果と分析

### シナリオテスト結果の比較

| モデル | n=2 (正常) | n≥3 (FP) |
|---|---|---|
| RadarLightUNet（2D ベースライン） | 31/35 (89%) | 4/35 (11%) |
| RadarUNet3DIntensity（30 epoch, BS=4） | 20/31 (65%) | 11/31 (35%) |
| RadarUNet3DIntensity（50 epoch, BS=8） | 7/31 (23%) | 23/31 (74%) |

- loss は 3 ケースとも ~0.92 で収束しているが FP 率が大幅に悪い
- epoch 増加・BS 増加でさらに悪化

### FP の原因分析

Conv3d の `(3,3,3)` カーネルが角度軸をまたぐため、2物体が近い range にいると隣接角度チャネルでも高確信度（conf ≈ 1.0）の検出が生じる。NMS 閾値 0.8 ではこれを抑制できない。

## 設計上の議論

### 訓練目標について
- **点ラベル（delta）**: BCE の正負不均衡が極端になり学習不安定 → 採用しない
- **Gaussian ラベル（現状）**: 正しいアプローチ。2D モデルでは問題なく機能している

### kernel_size=(1,3,3) 案
- 角度軸をまたがないため FP は減る可能性がある
- ただし「角度 A と角度 B の強度比較」が不可能になり、3D Conv の本来の意義が失われる → 採用しない

### 検出段階の設計
- **閾値 NMS（現状）**: 閾値チューニングが必要、FP が多い
- **top-K=2 固定**: FP は消えるが物体数固定前提でシナリオ依存
- **end-to-end 検出**: 検出自体を学習、CFAR との公平な比較が可能 → 理想的

3D CFAR と比較するうえでも、閾値手動チューニングが不要な end-to-end 検出が望ましい。

## 追加実験：ラベル設計の試行錯誤（ブランチ: feature/3d-conv-intensity-focal-loss-point-label）

### 方針

FP の根本原因は Conv3d (3,3,3) が角度軸をまたぐため、隣接チャネルにも高確信度の応答が生じること。  
NMS 閾値での対処は不可能なため、**学習段階でモデルに隣接チャネルの活性化をペナルティとして与える**方向で検討。

### ステップ1：角度軸のみ点ラベル化

- Gaussian ラベルの角度軸方向の拡散を止める（最近傍チャネル1つだけに割り当て）
- (d,r) 空間の Gaussian と損失関数は現状のまま

**結果**：

| モデル | n=2 (正常) | n≥3 (FP) |
|---|---|---|
| Gaussian 角度軸 + Gaussian(d,r) + BCE+Dice（従来） | 65% | 35% |
| 最近傍1ch + Gaussian(d,r) + BCE+Dice | 48% | 39% |

FP 率はほぼ変わらず、正検出率が低下。  
原因：角度軸の Gaussian 重みが (d,r) 方向の空間学習の補助も担っていたため、絞ることでドップラー方向の精度が低下したと考えられる。

### ステップ2：完全点ラベル + Focal Loss

- 正解ラベルを最近傍チャネルの1ピクセルだけ 1.0 に変更
- 損失関数を Focal Loss（α=0.25, γ=2.0）に変更
- `n_pos` 正規化（`mean` では正例2px / 全体40000px で勾配が消えるため）

**実装上のトラブル**：
- `mean` で正規化すると loss ≈ 0.0000、hit_rate = 0 の自明解に収束（正例が全ピクセルの平均に埋もれる）
- `sum / n_pos`（正例数で正規化）に変更して解決

**結果**：
- loss は 2.0 → 0.28 に収束（学習自体は進む）
- conf 最大 0.37（vehicle のみ）、cyclist は検出不能
- NMS 閾値を 0.3 まで下げても検出精度は低い

**失敗の原因**：  
点ラベルは空間的な学習信号を失う。Gaussian ラベルは「入力パターン → 正解位置」のマッピングを周辺ピクセルの勾配で学習させていたが、点ラベルでは1ピクセルの勾配しかなく、モデルが「どの入力パターンに反応すべきか」を学べない。  
vehicle の反射点と重心のずれ補正など、暗黙の回帰能力も失われた。

### 設計方針の結論

- **ヒートマップ生成と検出の分離**：モデルは Gaussian ラベルで良いヒートマップを作ることに集中し、FP 抑制は検出段階（NMS 改良）で対処する
- **完全 end-to-end**（DETR スタイル）は理想的だが、アーキテクチャから作り直しが必要
- SSD 的な anchor 回帰も候補だが、現状のアーキテクチャで1つずつ変更しながらアブレーションで進める方針

### Focal Loss の実装メモ（参考）

論文の式：`-α_t (1-p_t)^γ log(p_t)` では α_t は正例 α、負例 1-α（非対称）  
現実装は正例・負例ともに α を使用しており、負例への罰則が論文より弱い。  
点ラベルを使う場合は論文の非対称 α_t に変更することで FP 抑制が強まる可能性がある。

## ステップ3：CenterNet 式 Focal Loss + skip 接続削除（ブランチ: feature/3d-conv-intensity-focal-loss-point-label）

### アーキテクチャ変更：元入力の skip 接続を削除

`RadarUNet3DIntensity` の head で元の入力 RD マップを結合していた部分を削除。

```python
# 変更前
out = self.head(torch.cat([feat, x_3d], dim=1))  # fixed_channels + 1 → 1

# 変更後
out = self.head(feat)  # fixed_channels → 1
```

**理由**：2D モデルでは Conv2d が角度チャネルを混合するため、元の角度別 RD マップを head で足し戻す必要があった。3D モデルでは角度が空間次元として保持されるため不要。むしろ隣接チャネルの raw 信号が混入する原因になりうると判断。

### ラベル設計

- 角度軸：最近傍チャネル1つのみ（Gaussian 拡散なし）
- (d,r) 空間：Gaussian ブロブ（従来通り）

### 損失関数：CenterNet 式 Focal Loss

Gaussian ラベルに対して Focal Loss をかける設計（点ラベルと Gaussian の両立）。

```
正例(y=1):  -(1-p)^α · log(p)
裾野(y<1):  -(1-y)^β · p^α · log(1-p)   ← y で罰則を緩和
```

正例・負例を別々に正規化して同等に扱う（正例2px / 全体40000px の不均衡対策）：

```python
return pos_loss.sum() / n_pos + neg_loss.sum() / n_neg
```

**実装上のトラブル**：
- `decode_peaks_from_logits` の `while True` ループが初回学習後に無限ループ → 勾配爆発でロジットが極端に大きくなり全ピクセルが conf > 閾値になったため
- 対処：`while len(results) < max_peaks` に変更（上限10）＋ `clip_grad_norm_(max_norm=1.0)` を追加
- 学習率 1e-3 では学習曲線がギザギザに不安定 → 1e-4 に下げて安定化

### 結果

| モデル | n=2 (正常) | n≥3 (FP) | n=0 | n=1 |
|---|---|---|---|---|
| 3D (30ep, BS=4) 元 | 65% | 35% | - | - |
| 角度軸絞り + Gaussian(d,r) + BCE+Dice | 48% | 39% | - | - |
| CenterNet + skip 削除（LR=1e-4） | 35% | 16% | 13% | 36% |

FP 率は大幅に改善（35% → 16%）したが、正検出率が低下（見逃しが増加）。

### ブランチ全体の結論

閾値 0.8 での詳細分析：全 31 ステップで n≥3（FP）。各ステップに 4〜8 個のピークが conf ≈ 0.83〜0.99 で並ぶ。正しい検出（cy_dr=0, ve_dr=0）は含まれているが、同じ物体に対して複数の角度チャネルで高確信度ピークが立つ。

**Conv3d (3,3,3) は角度軸をまたぐ特徴抽出が可能だが、同時に隣接チャネルに高確信度 FP を生む。ラベル・損失関数・学習率を変えても構造的に解消できない。閾値 NMS で単一ピークを得ることはこのアーキテクチャでは困難。**
