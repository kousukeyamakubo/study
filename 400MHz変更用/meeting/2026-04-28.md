## 研究への適用方針

### アーキテクチャ設計の問題点
- 現状の「チャネル = 角度」設計は先行研究的な根拠がなく、指導教官の印象が良くなかった
- 指導教官は先行研究の有無を重視する傾向がある

### サーベイ結果の整理

| 論文 | 年・会議 | 現研究への関連 |
|---|---|---|
| RAD tensor NN | ICCV 2019, 被引用260 | 最も直接的。RAD テンソルを3次元として扱う設計原則を借用できる |
| SSMRadNet | WACV 2026, 被引用2 | パラダイム比較図が使える。ADC Cube 入力だが方式が異なる |
| 3D-UNet | 2016 | 医療画像向け、等方的3Dボリューム前提なので直接適用は難しい |

### 方針
- RAD tensor NN の設計原則（角度軸を空間軸として扱い Conv3d で処理）を借用
- 「同じ手法を再現する」ではなく「同じ設計原則を別ドメインに適用する」という立て付け
- **新規性の所在**: 28GHz ISAC の時分割制約（チャープ数制限・短時間センシング）という既存研究にない設定への適用
- 追加サーベイ（2022〜2025）で同じ設定に近い先行研究がないか確認する必要あり

### スライド構成案
1. 前回振り返り（①ヘッド独立化の学習結果 + 学習曲線）
2. サーベイ整理（SSMRadNet のパラダイム比較図を軸に、Convolution パラダイムを選ぶ根拠）
3. 今後の方針（RAD tensor NN の設計原則採用 + 新規性の所在を明示）
4. 先生に問う（追加サーベイの方向性、設計方針への合意）

## ADC Cube の適用可能性

### Y の形状
```
Y: (N_chirp, N_ant, rx_sample) = (89, 16, ~3003)
```

### ADC Cube 入力が困難な理由
- 今の研究は OFDM ライク方式 → ベースバンドで帯域幅全体をサンプリング
  - サンプリングレート ≈ BW = 400 MHz → N_sample ≈ 2190 サンプル/チャープ
- SSMRadNet が想定する FMCW（77GHz 車載）はビート信号（IF）をサンプリング
  - IF サンプリングレート：10〜40 MHz 程度 → N_sample ≈ 256〜1024

| | ADC Cube 入力 | RD マップ入力（現状） |
|---|---|---|
| 入力サイズ | `(89, 16, 3003)` ≈ 427万要素 | `(10, ~89, ~190)` ≈ 17万要素 |
| 適用可否（本研究設定） | 計算コスト上の課題大 | ✓ |

- 「同じ BW なら FMCW の方がサンプル数が少ない」理由：FMCW はビート信号のみサンプリングするため
- BW が広いほどサンプル数は増える（OFDM・FMCW どちらも）が、同 BW 比較では方式の差の方がインパクト大

→ スライドで「ADC Cube 入力が困難な理由」として使える論拠になる

## ミーティング結果（指導教官との議論）

### 決定した比較実験の構成

論文（RAD tensor NN）の工夫を一部取り入れて以下3手法で比較する：

| 手法 | 位置づけ |
|---|---|
| 3D CFAR | 古典的信号処理ベースライン |
| 3D Conv（強度のみ） | DL 基本構成（RAD tensor NN の最小適用） |
| 3D Conv（座標情報付き） | RAD tensor NN に倣った本命構成 |

- 3D CFAR は `monte-carlo-simulation.ipynb` で実装
- 3D Conv 2本は `check.ipynb` で新アーキテクチャとして実装
- 入力テンソルを `(B, 10, H, W)` → `(B, 1, 10, H, W)` に変形して Conv3d で処理
- 座標情報付き版はチャネルに `[強度, 角度インデックス, ドップラーインデックス, レンジインデックス]` を持たせる

### ブランチ方針
- `feature/3d-conv-basic` — 3D Conv（強度のみ）
- `feature/3d-conv-coord` — 3D Conv（座標情報付き）
- `feature/3d-cfar` — 3D CFAR
