# シミュレーション仕様・物理背景

シミュレーションを触るとき、または物理的な挙動を解釈するときに参照する。

## レーダーシステム仕様

| パラメータ | 値 |
|---|---|
| キャリア周波数 | 28 GHz |
| 帯域幅 (BW) | 400 MHz |
| アンテナ数 | 16 |
| シンボル時間 | 5.575 μs (CP込み) |
| サンプリング時間 Tc | 2.545 ns |
| チャープスロープ μ | BW_sub / T_symbol × 0.98 |
| チャープ数 N_chirp | 89 |
| レンジ分解能 | c × Tc / 2 ≈ 0.38 m/bin |
| レンジビンオフセット | 620 サンプル（受信バッファの先頭を読み飛ばす分） |

## シナリオ設定

電磁波シミュレーター **WaveFarer** でシナリオを生成し、受信信号（CSV）を使って検証を行う。

| 項目 | DICOMO 時 | 現在 |
|---|---|---|
| 環境 | 建物なし（見通しあり） | 建物あり（NLOS 交差点） |
| シミュレーター | WaveFarer | WaveFarer（シナリオ更新） |

想定環境: プロジェクトで想定している**建物により見通しの悪い交差点**（NLOS 環境）。

## データパイプライン

```
WaveFarer（外部 EM シミュレーター）
    ↓ CSV（複素インパルス応答: Time / 振幅 / 位相）
0601meeting/rad_from_csv.ipynb
    ↓ Cyclist_env_RDA_2nano.py を介して FFT 処理

    ↓

```

### CSV フォーマット

| カラム | 内容 |
|---|---|
| `Time (s)` | 受信時刻 |
| `\| Total Complex Impulse Response total \| (W)` | 受信電力（振幅） |
| `Phase( Total Complex Impulse Response total ) (rad)` | 受信位相 |

### Cyclist_env_RDA_2nano.py の役割

EM シミュレーターではなく**レーダー信号処理モジュール**。
WaveFarer CSV の受信信号を `rx_multiple()` で受け取り、`FFT()` で RD マップを生成する。
`learn_data_generator.ipynb`（内製シミュレーター側）でも同じモジュールを使用している。

## WaveFarer シミュレーションの既知問題

### 多重反射路の混入

WaveFarer は物理的に正確な EM 伝播を計算するため、意図しない反射路が強く現れることがある。

| 反射路 | 強度 | 問題 |
|---|---|---|
| 車両 → 建物 → アンテナ | 強い | 車両の真位置とは異なる RD ビンにピークが出る |
| アンテナ → 建物 → アンテナ | 中程度 | 静止物体として現れる（速度=0 付近のビン）。現状は間引き処理で除去しているが確信の根拠が不明確 |

### RD マップ生成コードの速度付与バグ

現状の `rad_from_csv.ipynb` / `FFT()` は、反射路の種別に関わらず**ターゲット（車両）の速度をすべての反射路に付与**している。  
車両 → 建物 → アンテナ の反射は本来ドップラーシフトが異なるが、現状のコードでは車両と同じ速度として処理されてしまう。

## 物理的な注意事項

### 車両のレンジビンずれ

RD マップ上に現れる車両のピーク座標は、真値（ground truth）より**数ビン近距離側にずれる**。

- **原因**: 真値は車両の重心位置で定義されているが、レーダー反射は車両の最近接面から返ってくるため
- **ずれ量**: 3〜5 ビン程度（物理距離で約 1〜2 m に相当）
- **対処**: 誤差として許容。モデルは「車両だと判断したらピークをやや遠く予測する」ことを期待している
- **サイクリストへの影響なし**: 現状サイクリストは歩行者モデル（点目標）を使っているため同様のずれは発生しない
