# 実測フェーズ（ATLAS）

24GHz 評価キット ATLAS を建物 5F の窓際に置き、道路を走る自転車・歩行者を測っている。
このファイルは、センサの確定仕様・データの処理の流れ・既知の注意点を 1 か所にまとめたもの。
週ごとの結果と判断は `weekly/MMDD/README.md` にあり、ここには**週をまたいで効く知識**だけを置く。

出典: `weekly/0727/ANALYSIS_OVERVIEW.md`・`weekly/0727/atlas_dat_format.md`・`weekly/1001/processing.md`・
`weekly/1001/README.md`・`weekly/0928/README.md`（2026-10-05 時点）。数字の根拠はそれぞれの出典にある。

---

## 1. 何を確かめようとしているか

- 道路上の自転車・歩行者を、距離−時間の軌跡として取り出せるか（**成立した**。10/1）
- 走っているレーン（道を横切る方向の位置、約 1 m 間隔）の違いが、測った距離 $R$ に現れるか（**未判定**。近い端が見えていない）
- 10/2 の指摘で、上位のゴールは「**目標を識別できるか**」。レーン識別はその手前の問い

検出対象は車両ではなく自転車と歩行者（車両 10 m/s は速度が折り返すため。§2）。

## 2. センサ：ATLAS（エスタカヤ、24GHz FMCW、TX2 × RX4）

T14RE（79GHz）は最大距離 50 m・最大速度 ±1.44 m/s で調整できず、2026-07-17 に不採用。

### 確定している値（解析で使う値）

| 項目 | 値 | 備考 |
|---|---|---|
| 開始周波数 / 帯域 | 24.06 GHz / 177.2 MHz | ヘッダ 0x28 に帯域が入っている |
| 1フレーム | 32 チャープ × 4 RX × 256 サンプル（int16）= 65,536 byte | 軸順 (Frame, Chirp, Rx, Sample) |
| TX の並び | **チャープごとに交互**（偶数 = Tx1、奇数 = Tx2）→ **TX あたり 16 チャープ** | 先頭チャープが Tx1 であることは仕様書で確定 |
| IF 信号 | **実数サンプル**（IQ ではない） | 距離 FFT は片側 129 点 |
| チャープ間隔 | 325 µs（同じ TX の繰り返しは 650 µs） | |
| フレーム周期 | 0.2 s | 30 s 収録で 150 フレーム（欠損ゼロを確認） |
| **距離分解能** | **0.846 m**（= c/2B）、129 ビン、0〜108.3 m | ヘッダの `range_res`（0.21 m など）はゼロ埋めの表示刻み。使わない |
| **速度分解能** | **0.5995 m/s**、16 ビン、−4.80〜+4.20 m/s | |v_r| > 4.8 m/s は折り返す |
| RX の並び（`.dat` 内） | Rx2, Rx1, Rx3, Rx4 | 空間順に戻すには `[1, 0, 2, 3]`。`atlas_export.py` の `VIRT_ARRAY` は対応済み |
| 仮想アレイ | 7 素子（基板のダミーアンテナは MIMO に使わない） | 方位分解能 14.5°（文書値） |
| フレームごとのタイムスタンプ | **無い** | 時刻は「フレーム番号 × 0.2 s」。外部と同期するには同期イベントが要る |

sim（28GHz）との対比で距離分解能を並べるときは、sim の 0.38 m/bin と ATLAS の **0.846 m** を使う。

### 速度の目安

- 自転車 2.5 m/s・歩行者 1.3 m/s は折り返さない。車は**徐行 15 km/h 程度まで**
- 径方向速度は $v_r = v X / R$（$X$ は最接近点からの走路上の距離）なので、最接近点の前後で 0 に近づく

## 3. 設置と現場

- 研究棟 5F の窓から道路を見下ろす（設置高 $h \approx 15$ m）。部屋はレンタルで固定できないため、**録画ごとに設置条件を記録**し、条件の比較は同じ回に連続で撮る
- **窓は半分だけ開放**。窓枠が主ビームに入り、0.85 m 付近に 65〜70 dB の静止クラッタが出る（MTI で消えるが開口を塞ぐ）
- 地上の目標は幾何的に $R \gtrsim 13$ m にしか現れない。近距離 0〜8 m は窓枠・三脚・操作者
- 全時刻に居座る静止物の残差の帯がある（10/1 の現場で $R \approx 18, 33\text{〜}34, 41.5$ m）
- 走路はコーンで囲み、コーンまでの斜距離をレーダー位置からレーザー距離計で測る（`weekly/1001/README.md` §5）。
  コーンの斜距離はレーダーから見た $R$ の真値として使い、斜距離から $y_r$（セットバック）を逆算する使い方はしない（誤差が約 4.5 倍になる）
- 人・自転車の反射中心は地上 $z \approx 1$ m なので、地面を測ったコーンの斜距離より $\Delta R \approx h z / R$（$R = 25$ m で約 0.6 m）短く出る
- 道幅 4 m、レーンは約 1 m 間隔。木はレーン 3 側の縁に並び、レーダーもレーン 3 側にある

座標系と、地上座標から $R$・$v_r$ を出す式は `weekly/0928/geometry.py`。

## 4. 処理の流れ

```
.dat（生の IF。FFT 前）
  │ ① weekly/0727/atlas_export.py        TX 分離 → MTI → 距離 FFT → 速度 FFT
  ▼
複素 RD テンソル .npz   (Frame, TX=2, RX=4, Doppler=16, Range=129) complex64
  │ ② atlas_ridge_track.py: moving_power_db   8ch を振幅で加算 → dB → DC ビン除外 → 速度方向に最大
  ▼
距離−時間の動体電力   (Frame, Range)   ← 距離−時間図はこれを描いたもの
  │ ③ build_ridges / pick_ridge          しきい値超えの極大をフレーム間で繋ぐ → 1 本選ぶ
  ▼
軌跡 R(t)
```

ボードは電波を出して A/D 変換するだけで、距離・速度の計算はすべて PC 側。各段の詳細は `weekly/1001/processing.md`。

```bash
python weekly/0727/atlas_export.py <file>.dat --outdir <dir>            # MTI あり（既定）
python weekly/0727/atlas_export.py <file>.dat --outdir <dir> --no-mti   # MTI なし（比較用）
```

### ① `atlas_export.py` の設計判断

- **ゼロ埋めしない**（`--n-fft 256`）。1 ビン = 真の分解能 0.846 m を保つ
- **複素のまま TX/RX を潰さない**。角度は後から `to_ra()` で計算できる（TDM の位相補正 $e^{-j\pi k/N}$ 込み）
- 窓は `hanning_matlab`（`np.hanning` は両端が 0 で、16 点のチャープ軸では 2 本失う）
- MTI は 1 フレーム内 16 チャープの平均を引くだけ（ベンダーコードに無い自作）

### ③ 軌跡の抽出（`atlas_ridge_track.py`）

- 距離ゲート 2 ビン（1 フレームで動ける 0.96 m）、ドップラーゲート 2 ビン、見失い 3 フレームまで、5 点未満は捨てる
- 本物の判定: 距離の時間変化の傾き `slope` とドップラー中央値の差が 1 m/s 未満、かつ |slope| > 0.3 m/s。満たすもののうち最長を採る
- 使ってきた設定: 日中 `--rmin 25 --rmax 55 --thr 22`、夜 R 20〜60 m・20 dB
- `atlas_track.py` は旧版（毎フレーム argmax で副ピークへ飛ぶ）。**使わない**

### レベルの目安

- 雑音床 12.9〜13.5 dB（屋内外でほぼ同じ）。dB はすべて**相対値**（校正係数が未入手）
- 目標は軌跡上で 22〜31 dB。単フレームしきい値 25 dB では歩行者を見逃すので、**フレーム間の追尾を前提にする**

## 5. 既知の注意点

### 解析を誤らせるもの

| 注意点 | 内容 | 対処 |
|---|---|---|
| **MTI は遅い目標を削る** | 平均を引くので $|v_r| \lesssim 0.3$ m/s が消える（0.3 m/s で約 −2 dB、0.15 m/s で約 −7 dB）。② で DC ビンも除く | 最接近点付近（$v_r \to 0$）はフレーム間差分（MTI なし RD の 0.2 s 前との差）を使う。`weekly/1001/analyze_night.py` の `framediff_excess` |
| 徒歩は特に削られる | $d = 23$ m の幾何で $|v_r| < 0.3$ m/s の区間は、徒歩で前後約 5.5 m（約 8 s）、自転車で約 2.8 m（約 2 s） | 同上 |
| MTI は目標が多い場面に弱い | 10/2 の指摘。今のシナリオ（1 人ずつ）なら成立する | 背景を引く方式の検討中。ただし単純な複素の背景差分は、静止物の反射が 30 s の中で変わるため成立しなかった（10/5） |
| **自動追跡が別の筋を拾う** | `pick_ridge`（最長を採る）が、隣の薄い筋や静止物の残差の帯（R ≈ 33, 41.5 m）を拾った走行があった（10/1 夜の No. 19, 22, 28 など） | 真値の経路が分かる収録では、経路上の総当たり（整合フィルタ）に置き換える。生の距離−時間図で必ず確かめる |
| 低速では判定が自動的に通る | 「slope とドップラーが一致」は遅い目標と植生（slope ≈ 0、ドップラー ±0.6）を区別できない | |slope| の下限（0.3 m/s）を置いている |
| 速度ビンを値で切ると漏れる | 刻みが 0.5995 m/s なので `|v| >= 0.6` と書くと ±1 ビン目（歩行速度）が落ちる | **ビン番号で切る** |
| `--n-fft` がリテラル 256 | GUI でサンプル数を変えると、黙って後半を捨てて分解能が落ちる（合成データで確認、**未修正**） | 設定を変えたら `hdr["n_sample"]` と一致しているか確かめる |
| MATLAB をそのまま移植すると壊れる | ベンダー MATLAB の `reshape` は `.dat` と軸順が違う。速度軸のキャリアもアプリは 24.06 GHz、MATLAB は 24.15 GHz | `atlas_export.py` を使う |

### 収録で守ること

- **操作者は録画中に動かない**。室内で動くと近距離の漏れ込みが 22 dB 跳ね、そのレンジサイドローブで 10〜15 m に偽目標が出る。
  捨てるなら「< 5 m に 30 dB 超があるフレームを丸ごと捨てる」
- 置き方・窓の状態を変えるたびに、前後で無人背景を 30 s 撮る
- レーンなどの条件は、ブロック内で順番をシャッフルする（10/1 夜はレーンと時間帯が交絡した）

### 窓の開閉

9/28 の検証で「窓を閉めると計測できない」としたが、10/5 の見直しで**言い過ぎの可能性が高い**と分かった。
窓を閉めたときの床の上昇はドップラー方向に平ら（雑音がドップラー成分に見えている）で、手前の距離帯ほど大きい（R 13〜20 m で +5.8 dB、40〜60 m で +0.4 dB）。
ガラスによる減衰は約 4 dB。人がいるデータで確かめるまで未確定（`meeting/2026-10-13.md`）。

## 6. 未確定のこと

「誤り」ではなく「まだ確かめていない」。何が言えなくなるかを併記する。

| 項目 | 影響 |
|---|---|
| レンジの絶対オフセット | 距離に未知の定数が乗りうる。相対変化と速度には効かない。コーンとの照合（遠い端で 1 ビン以内）が間接的な裏付け |
| 振幅の絶対値 | 絶対 SNR・RCS は語れない |
| 垂直ビーム幅・向き | データシートは入手不可。近い端（R 22〜28 m）が見えない原因の候補 |
| 素子間隔 λ/2・TDM 位相補正 | 角度にのみ効く。既知方向の目標で未検証 |
| ヘッダ 0x64〜0xB3 | 未同定。`Remove Static Clutter` のフラグが入っている可能性 |
| fs・サンプル数・PRI を変えられるか | 車両の速度折り返しへの対応を決める材料。未確認 |

### 角度

7 月に「方位分解能 14.5° なので角度は評価対象外」と決めた（単フレームの分解能の議論）。
10/5 の試し描きでは、角度−時間図で自転車レーン 1 の角度が +40° → −30° へ連続的に動いており、**軌跡としては角度が使えそう**。扱いは未決定。
