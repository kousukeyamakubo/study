## A. 得られた情報

### A-1. ATLAS の確定パラメータ（操作説明書 Chirp/Frame タブ p.9 / Scene タブ p.9）【文書】

| 項目 | 値（デフォルト設定時） | 出典 |
|---|---|---|
| Start Frequency（キャリア） | **24.0600 GHz** | Chirp/Frame タブ |
| Slope | 0.6923 MHz/µs | 同 |
| Sweep Bandwidth（帯域幅） | **0.1772 GHz = 177.2 MHz** | 同 |
| Samples per chirp | 256 | 同 |
| Sampling rate | 1.0000 Msps | 同 |
| Chirps per frame（Doppler ビン数） | **32** | 同 |
| Frame periodicity | 200 msec | 同 |
| Transmit Antennas | **2** | 同 |
| Receive Antennas | **4** | 同 |
| Range resolution | **0.1058 m/bin** | Scene タブ |
| Max Unambiguous Range | **26.9775 m** | Scene タブ |
| Max Radial Velocity | **±4.7957 m/s** | Scene タブ |
| Radial Velocity Resolution | **0.5995 m/s** | Scene タブ |
| Azimuth Resolution | **14.5 deg** | Scene タブ |

補足【推定】:
- レンジビン間隔 0.106 m は「最大距離26.98m ÷ 256サンプル」に一致。ただし帯域幅177.2MHzからの
  真の距離分解能は c/(2B) ≈ **0.85 m** で、ビン間隔より粗い（オーバーサンプリング）。
- Doppler ビン数 32 = Chirps per frame。±4.80 / 0.60 ≈ 16 で片側16・両側32ビンと整合。

### A-2. 設定変更の自由度【文書】
- Profiling タブの CFG で「**最大検知距離**」と「**速度分解能**」を選択 → `Load Config from PC and Send` で反映。
- 最大距離: デフォルト 26m。**200m チェックで最大 242m まで拡張可**。ただし
  「最大距離を優先するため距離分解能を落とす」＝**分解能とのトレードオフ**（107m 以下ならチェックを外す推奨）。
- 検出チューニング（Real-Time Tuning タブ）: CFAR 閾値（Range/Doppler 別）、静止クラッタ除去
  （Remove Static Clutter）、同一物体のピーク統合、FOV（角度 −90〜90°・距離・速度の表示範囲）。

### A-3. 出力データ（HANDOFF §3-⑥・§6 に直結）【文書】
- **測定データは `.dat` バイナリで保存**（例 `atlas_log_YYYYMMDD_HHMMSS.dat`）。→ HANDOFF §6 の
  「バイナリ＋自前パースが正解」という方針とそのまま合致。
- **IF Signal を出力可能**（Rx1〜Rx4 × Tx1/Tx2 を選択表示）。→ 生の中間周波信号に近く、
  **学習時と同一系統の FFT 処理を後段で再現できる可能性が高い**（HANDOFF §3-⑥の狙い）。
- 検出オブジェクト一覧を **CSV 保存可**（列: `rng[m], θ[deg], dop[m/s], peakval, x[m], y[m]`）。
- そのほか取得可能ビュー: Range Profile / Noise Profile、Azimuth-Range Heatmap、
  Doppler-Range Plot / Heatmap、X-Y Scatter。カメラ画像との同時保存・再生も可。

### A-5. T14RE 敗因（低い最大速度）を克服できるかの評価【推定】
- 最大速度 **±4.80 m/s**。歩行≈1 m/s ○、自転車 3〜6 m/s △（速い走行は折り返す）、車両 10 m/s 級 ✗。
- T14RE の ±1.44 m/s よりは大幅改善だが、**本番スケール（車両速度）はやはり測れない**。
  → これは HANDOFF §5 の段階論「**Step3: センサ仕様に合わせた縮小版 sim で学習**」を採る根拠に直結。

## B. 得られなかった情報（HANDOFF＋PDF を読んでも埋まらない）

### B-1. 物理・信号処理の未確定（PDF はアプリ操作書のため踏み込まない）
- **③ 最大距離の「由来」が文書に明記なし**。IF信号を出力（デチャープ後をADC）し、最大距離が
  分解能とトレードオフで可変な点から **ストレッチ処理と【推定】**できるが、文書での断定は不可。
  → 「620サンプルオフセット相当の観測窓を後処理で自由に置けるか」は不明（ストレッチなら不可の公算）。
- **IF信号が複素IQか実数か**が不明（プロットは実数波形に見える）。学習系FFTをそのまま流用できるかに影響。
- **`.dat` バイナリの内部フォーマット仕様が非公開**（列構成・ヘッダ・エンディアン等）。
  → HANDOFF §6 どおり**自前パーサの作成が必要**。T14RE 用パーサ（`0715/dat_inspect.py`）は構造参考のみ。
- レーダーの**データシート（RF仕様・アンテナ配置の実寸・角度FOVの厳密値）は 0721 に含まれていない**。
  Azimuth 14.5° は得られたが、仮想8ch の配列ジオメトリ（等間隔か等）は未記載。

### B-2. 電波法・運用面
- 技適済みとしか書かれておらず、**波形パラメータを技適範囲内でどこまで変えられるかの詳細が不明**
  （実質 CFG のプリセット選択に限られる可能性）。免許・実験局の要否は本キットでは非該当（技適品）。

### B-3. 研究運用上、ユーザー判断が要る未確定（HANDOFF §8 の残り）
- [ ] 新センサで測りたい**最初のシナリオ**（Step2 の sim/実測比較に使う条件）。
- [ ] `0715` のコミット状況（前セッションで未コミット・未プッシュ）。
- [ ] 角度推定の扱い: **ATLAS の Azimuth 分解能 14.5° は narrow モデルの角度グリッド（幅3°=1〜4°）と
      桁違いに粗い**。実測では角度推定をどう位置づけるか（比較対象外にする／粗い角度で妥協）が要相談。
