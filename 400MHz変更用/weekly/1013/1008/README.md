# N=16 で見逃し・誤警報 5% に届かせる（分析の計画、10/8〜）

ゴールと合格ラインの根拠は `../README.md`「今週の目的」と `meeting/2026-10-13.md`「3. 合格ライン」。
収録（実測側）のタスクは `../collect/`。ここはソフト側（分析）のタスクだけを書く。

> このフォルダ名は観測日ではなく、計画を立てた日（10/8）。使うデータは 10/1 夜

## ゴール

TS 22.137 表 6.2-1 カテゴリ 2 の数え方で、N=16 の ATLAS が **見逃し ≤5%・誤警報 ≤5%** に届く処理を決める。
決めた処理は固定して、週末の収録のデータで確かめる（決めるデータと確かめるデータを分ける）。

## 使うデータ：10/1 夜

10/5 は使わない。雨より、真値が作れないのが理由。

| | 10/1 夜 | 10/5 |
|---|---|---|
| レーン | 走行ごとに決まっている | 記録なし |
| コーンの斜距離・設置幾何 | 測ってある | 記録なし |
| 置き方 | 1 回の中で同じ | 途中で変わった可能性（水平の角度が 0.7〜1.2° ずれた） |
| 対象 | 徒歩・自転車 | 自転車・車（カテゴリ 2 の対象は人） |

- 対象は、真値の当てはめが時刻反転の対照を 1 dB 以上上回った 12 本（徒歩 No.1, 3, 5, 9、自転車 No.19〜24, 27, 28）。`../1001/README.md` C と同じ
- 評価する区間は、見える帯の R 30〜49 m（中・遠の帯）。近い帯（21〜30 m）はビームが当たっておらず、偶然で当たる床と区別できない（`../1001/README.md` C）
- フレーム数は、中 273・遠 209（12 本の合計）

## タスク

### T1. 3GPP の数え方で測り直す

今の評価（`../1001/cfar_compare.py`）からの変更点：

| | 今 | 変えた後 |
|---|---|---|
| 事象の単位 | 軌跡上のセル | 1 フレーム ＝ 1 事象 |
| 検出の単位 | CFAR のセル | セルを物体にまとめる（クラスタリング） |
| 対応づけ | 距離 ±1 ビン かつ ドップラー ±1 ビン | **BEV の位置で 2 m 以内だけ**。ドップラーは N で幅が変わるので使わない |
| 真値 | 3 方式の床超過の平均に当てはめた等速軌跡 | 同じ。v, t0 は N=16 で決めて固定する |
| 誤警報 | セル単位の割合（1e-3） | 目標ありの回：目標に対応づかない物体の割合（TR 38.765 の Type 2）。目標なしの回（Type 1）は週末の無人背景で出す |

- 見逃し ＝ 評価区間に目標がいるフレームのうち、2 m 以内に物体がないフレームの割合
- 物体と真値は 1 対 1 で対応づける（TR 38.765 §4.1）
- 出すもの：帯ごと・走行ごとの見逃しと誤警報（Type 2）。今の検出率 0.51 / 0.65（中 / 遠）との対応も書く

### T2. パラメータを振って 5% に届かせる

- 振るもの：CFAR のしきい値・訓練セルとガードセルの幅、物体へのまとめ方
- 見逃しと誤警報（Type 2）が両方 5% 以下になる組み合わせを探す。両方を同時に満たせないときは、2 つの指標の兼ね合いの曲線を出す
- 選んだ組み合わせを固定する。10/1 夜のデータに合わせすぎていないかは、T3 で確かめる

### T3. 週末のデータで確かめる

- T2 で決めた処理をそのまま週末のデータに掛け、見逃し・誤警報（Type 1・Type 2）を出す
- 撮るものは `../collect/` で決める（確かめる用の走行は置き方を固定する、無人の背景、高さと傾きの記録）

## 決めること

| | 内容 | 今の案 |
|---|---|---|
| 1 | 検出を BEV に写す方法 | まず距離だけで写す。目標の側のレーンにいると仮定し、X = √(R² − d²)。角度で横の位置も出すかは後で決める |
| 2 | 物体へのまとめ方 | 距離−ドップラーで隣り合うセルをまとめ、電力最大のセルを代表点にする。ドップラー方向にまとめるのは N で効き方が変わる点に注意 |
| 3 | 5% と言うのに要る事象の数 | 見逃し 0 件なら約 60 事象が目安（3/n ≤ 0.05）。中・遠で約 480 フレームあるが、同じ走行のフレームは独立ではない |
