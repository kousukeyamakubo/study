# 【アーカイブ】ミリ波レーダー実機仕様（TITAN T14RE）— 不採用

**2026-07-17 のミーティングで T14RE は使用しないことが決定**（距離50m・速度±1.44m/s・
Dopplerビン16 の制約が検証目的に対して厳しすぎるため）。別センサに切り替え。
本ファイルは T14RE の調査記録として保存。`0715/` の解析スクリプト群（dat_inspect.py 等）も
T14RE 専用だが、蒸留の手順・RDマップ化・比較の考え方は新センサでも流用できる。

原本ドキュメント: `0715/hw_docs/`（PDF 7冊、2026-07-15 入手）。本ファイルはその蒸留版。

## 電波法上の制約（重要）

- 技適はメーカー提供プリセット Cfg の出力方式で取得されている。**カスタム波形（帯域幅・チャープ数の自由変更）は技適対象外＝日本国内で使用不可**
- したがって「実機設定をシミュレーションに寄せる」は不可能。**RDマップのリサンプリングで学習時グリッドに合わせる一択**
- 日本国内でのみ使用可。分解・改造・技適ラベル剥がし禁止

## シミュレーション仕様との対比

| 項目 | シミュレーション | 実機（Mid） | 実機（Short） |
|---|---|---|---|
| キャリア周波数 | 28 GHz | 79 GHz帯 | 79 GHz帯 |
| 実効帯域幅 | 400 MHz | 614 MHz | 3354 MHz |
| レンジ分解能 | 0.38 m/bin | 0.244 m/bin | 0.045 m/bin |
| Dopplerビン数（チャープ数） | 89 | 16 | 16 |
| 最大速度 | − | ±1.44 m/s | ±1.44 m/s |

### ギャップ分析

1. **レンジ軸**: Mid が最も近い（0.244 → 0.38 m/bin へリサンプリング）。屋内パイロット計測（<9m）なら Short も選択肢（分解能過剰だがダウンサンプリングで対応可）
2. **Doppler軸が最大のギャップ**: 16ビン vs 89チャープ。単純補間では情報が足りず、扱い（リサンプリング／複数フレーム結合／モデル側の再学習）は要検討
3. **最大速度 ±1.44 m/s**: 歩行速度程度まで。**車両速度の実測はこの機材では原理的に不可**（折り返し発生）。初回計測プラン（静止→低速移動）とは整合
4. **キャリア 79GHz vs 28GHz**: 速度軸を物理単位（m/s）に換算すれば軸としては整合可能だが、RCS・伝搬特性のドメインギャップは残る（「学習=sim／テスト=real」の検証項目そのもの）

## データ取得経路

### 推奨: RAW（生IQ）+ Python 自前処理

実機側FFTは窓関数等の処理内容が非公開のため、**RAW取得 → 既存のシミュレーションと同じFFT処理系**（`Cyclist_env_RDA_2nano.py` 相当）でRDマップ化するのが学習時と処理を揃える最短経路。

```
pyserial（115200bps・LF・プロンプト "mmwDemo:/>"）で Cfg を1行ずつ送信（各行 "Done" 待ち）
  → cv2.VideoCapture(idx, cv2.CAP_MSMF) で取得（UVCカメラとして認識）
     ※ CAP_PROP_CONVERT_RGB=0, CAP_PROP_FORMAT=-1 必須。DirectShow不可
  → int16リトルエンディアンのIQバッファ
  → reshape: (Frame, Chirpset, Tx, Rx, Sample, 2) → I + jQ で複素化
  → レンジFFT・DopplerFFT → RDマップ
```

- データはヘッダなしの純バイナリ。パラメータ（Frame/Chirpset/Tx/Rx/Sample数）は Cfg 側の値を自前管理
- 次元順（遅い→速い）: フレーム → チャープセット → チャープ(TX) → 受信アンテナ(RX) → サンプル → (I, Q)
- **注意**: 冒頭数フレームは All-0 が来ることがありスキップ推奨。RAWは I→Q 順、FFT出力は 虚→実 順で異なる
- 依存: Python 3.9+、pyserial、numpy、opencv-python
- ポート特定: `t14retool -deviceInfo`（COMポート番号とキャプチャデバイスindexが返る）。USB VID/PID = 0x1364/0x802B
- 公式サンプル: `T14reSample.py`（CD-ROM内、取得→CSV保存のワンショット例）

### 代替: DemoKitApp（GUI）

`TitanDemoKitAppT14re.exe`（インストール不要、CD-ROMからコピー）。接続 → Cfg読込（自動でセンサー起動）→ 表示。

- 表示: RDヒートマップ（Doppler-Range Heatmap）、Range Profile、点群、検出一覧（CFAR）
- 保存: 測定データ `.dat`（内部フォーマット非公開 → 下記で解読済み）、検出一覧のCSV
- 初回の動作確認・デモ画面撮影には有用

### `.dat` ファイルの内部構造（2026-07-15 実データ解析により同定）

**注意: 文書由来の情報と実ファイル解析からの類推を区別すること。**
公式ドキュメントに `.dat` の内部構造の記載は無い。以下の構造はRAW Cfg・Short プリセット・
10秒録画のファイル1本（19,661,056 byte）の解析による推定で、根拠は
①サイズの算術一致（256 + 196,608×100）②ヘッダ解読値と Cfg説明書の Short 値の一致
③RDマップの物理的妥当性（静止物距離の安定・フィルタ減衰域が仕様どおり）の3点。

```
[ヘッダ 256 byte] [フレーム 196,608 byte] × N   （タイムスタンプ無し、時刻は n×フレーム周期）
```

- ヘッダ【類推】: Cfg由来パラメータが double / int32 (LE) で並ぶ。判明済みオフセットは
  `0715/dat_inspect.py` の `parse_header()` を参照（開始周波数・スロープ・サンプル数・
  チャープ数・TX/RX数・距離/速度の分解能と最大値）
- フレーム部【文書+類推】: USB転送フォーマット（ソフトウェア説明書 p.9-11 に記載:
  int16 LE、チャープセット→TX→RX→サンプル→I/Q の順、RAWは I→Q）が
  **無加工で連結されている**（連結されているという点が類推）
- 解析・可視化ツール: `0715/dat_inspect.py`（ヘッダ表示＋RDマップ生成）、
  `0715/motion_check.py`（動体検出・時間×レンジ図）
