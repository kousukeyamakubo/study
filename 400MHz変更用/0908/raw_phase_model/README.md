## 設計の要点

- **DBF を経由しない**: 7素子の複素RDを実部・虚部14chとしてそのままモデルに渡す。
  角度への変換（=座標変換）ごとネットワークに学習させる
- **出力は地上 (X,Y) グリッド**: 既存モデル（`docs/model.md`）の出力軸は
  角度グリッド（N_FIXED）だが、DBF を使わない以上そこに角度軸を置く理由がない。
  8/17 の決定「ラベル＝地上座標の点」とも整合する
- **(Doppler,Range) と (Y,X) は別の空間**: Range は斜距離、角度は素子間位相差から求まる。
  どちらも非線形な変換なので、単純なアップサンプリングでは繋がらない。
  エンコーダで固定サイズの特徴に圧縮し、デコーダで地上グリッドへ再展開する構成にした

## まだ決めていないこと（次回チャット向けメモ）

- **アーキテクチャそのもの**: 層の種類・段数・チャネル数は何も決めていない。今の
  `RawPhaseGroundNet` は conv 1層 + 補間 + 1x1 conv というほぼ形だけの中身で、
  学習に着手する段階で作り直す前提（意図的に決め込んでいない）
- **地上グリッドの範囲・分解能**（`GRID_X_RANGE_M`, `GRID_Y_RANGE_M`, `GRID_RES_M`）: 未検証の
  プレースホルダ。週末の撮影でシナリオの実配置が分かってから決める
- **損失関数**: 既存モデルは alpha-balanced Focal Loss（`docs/model.md`）だが、
  クラス不均衡の度合いが角度グリッドと地上グリッドで違うはずなので要検討
- **教師データ**: S4（`meeting/2026-09-08.md`）の「教師テンソルの組み立て」がまだ無いため、
  このモデルで学習を回すこと自体、今週末のデータが揃うまでできない
- **`0908/postprocess/`との関係**: このモデルが出す地上グリッドのクラスマップも、
  結局はピーク抽出 → NMS → 追尾という同じ後処理を通ることになるはず。
  `0908/postprocess/track.py` はモデル非依存に書いてあるので、
  出力形式さえ合わせれば転用できる見込み（未検証）
