# ATLAS 解析プログラム 全体像

`.dat` フォーマットの詳細は `atlas_dat_format.md`、録画ごとの条件は `dat/README.md`。
本ファイルは**何をしているかを思い出すため**の最小限のまとめ。

## 1. 全体の流れ

```
ATLAS ボード ──USB──> DemoKitApp ──> .dat（生サンプル。FFT前）
                                       │
                        atlas_export.py │  ← 唯一の入口
                                       ↓
                            *_rd.npz（複素 RD テンソル）
                                       │
                  ┌────────────────────┼────────────────────┐
        atlas_ridge_track.py    atlas_rd_gif.py      to_ra()（角度）
          軌跡＋判定               時系列 GIF        必要時のみ呼ぶ
```

ボードは電波を出して A/D 変換するだけ。距離・速度の計算は全部 PC 側。
`.dat` には FFT 前の生サンプルしか入っていないので、処理は自分で書く必要がある。

## 2. ファイルの役割

| ファイル | 役割 |
|---|---|
| `atlas_export.py` | **入口**。`.dat` → 複素 RD テンソル npz。軸はヘッダから毎回再計算 |
| `atlas_dat_parse.py` | フォーマット解読用（役割終了・凍結）。`parse_header` / `load_frames` だけ共有 |
| `atlas_provenance_check.py` | 解読が正しいことの検査 10 項目。反証可能な形にしてある |
| `verify_config_change.py` | 既知正解の合成 `.dat` で往復テスト。設定を振ってもコードが追従するか |
| `atlas_ridge_track.py` | **軌跡抽出（現行）**。フレーム間連続性で拘束。複数尾根を出す |
| `atlas_track.py` | 旧版。毎フレーム argmax なので弱い目標で副ピークへ飛ぶ。**使わない** |
| `atlas_rd_gif.py` | RD マップを時系列 GIF に |
| `atlas_matlab_port.py` | ベンダー MATLAB (`matlab/AN24_*.m`) の移植。参照用 |

## 3. `atlas_export.py` の処理（形の変化）

| # | 処理 | 形 | 何のため |
|---|---|---|---|
| ① | `load_frames` | (50, 32, 4, 256) | バイト列の並べ替えのみ。計算しない |
| ② | TX 分解 `[tx::2]` | (50, **2**, 16, 4, 256) | TDM。混ぜると位相が飛ぶので必須 |
| ③ | `transpose` | (50, 2, 4, **16, 256**) | 次に Chirp 軸で FFT するため |
| ④ | MTI（チャープ平均を引く） | 変化なし | 静止クラッタを消す |
| ⑤ | レンジ FFT `rfft(n=256)` | (…, 16, **129**) | ここで距離が出る。実数なので片側 129 点 |
| ⑥ | ドップラー FFT + `fftshift` | (…, **16**, 129) | ここで速度が出る |

出力 `(Frame, TX, RX, Doppler, Range)` complex64。Range 0〜108.33 m / 0.8464 m 刻み、
Vel −4.80〜+4.20 m/s / 0.5995 m/s 刻み（16点を fftshift するので負側が1本多い）。

### 設計判断（迷ったら思い出す用）

- **ゼロ埋めしない**（`n_fft=256`）: 1 ビン = 真の分解能 0.846 m を保つ。アプリ表示の 0.21 m は補間なので持ち込まない
- **複素のまま TX/RX を潰さない**: 角度は後から計算する。TX 順序が未確定なので判断を固定しない
- **`hanning_matlab` を自作**: `np.hanning` は両端が 0 になり、16 点のチャープ軸では 2 本失う

## 4. 確定していること

| 内容 | 根拠 |
|---|---|
| ヘッダの各項目の意味と位置 | 操作説明書 12 項目 + 冗長フィールド 5 個が**厳密一致**（相対誤差 0） |
| データ部の軸順 (Frame, Chirp, Rx, Sample) | フレーム長で余り 0（4 軸の積が一致）+ 位相コヒーレンス |
| IF は実数サンプル（IQ でない） | 複素と解釈したときの正負対称性 相関 0.993 |
| TX は交互（ブロックでない） | 隣接チャープ位相差 0.003 rad 対 1.144 rad（380 倍差） |
| レンジ軸・速度軸のスケール | MATLAB と同一式 + ヘッダ冗長性 + 合成データ往復テスト（速度誤差 0.00） |
| 真の距離分解能 0.846 m / 物理上限 108.3 m | ヘッダ 0x28 の実効帯域 177.2 MHz から。表示値 0.21 m / 53.96 m とは別物 |
| 自転車 3 本の検出 | レンジ変化率と Doppler が独立に 1 ビン以内で一致（0.09 / 0.28 / 0.43） |

## 5. あいまいなこと

「間違っている」ではなく「まだ確かめていない」。**何が言えなくなるか**を併記する。

| 項目 | 影響 | 潰し方 |
|---|---|---|
| **レンジの絶対オフセット** | 距離に未知の定数が乗りうる。相対変化と速度は無影響 | 既知位置リフレクタ |
| **振幅の絶対値** | `FuSca`・校正係数8個が未入手 → **dB は全部相対値**。絶対 SNR / RCS は語れない | メーカー問い合わせ |
| **角度の符号** | どちらの物理 TX が `Tx1` か `.dat` から判別不能 → 左右が反転しうる。単調変化という事実は安全 | メーカー問い合わせ or 既知方向の目標 |
| **MTI の副作用** | ベンダーコードに無い自作。ゼロドップラー近傍を削るので**遅い目標を減衰させる** | `--no-mti` と比較 |
| **TDM ドップラー位相補正** `exp(-jπk/N)` | 自分で導出。ベンダーコードに無い。角度にのみ効く | 既知角度の目標で検証 |
| **素子間隔 λ/2** | MATLAB の角度軸の前提。未実測 | メーカー問い合わせ |
| **フレーム落ち** | タイムスタンプが無く検出不能。落ちれば時間軸が縮みレンジ変化率が過大評価。**ただし Doppler と一致した事実が間接的な証拠** | 同期イベント（金属板）を先頭と末尾に入れる |
| **`atlas_ridge_track.py` のパラメータ** | しきい値 25 dB・ゲート 2 bin・最小 5 フレームは手選択。主尾根の採否は Doppler 一致という独立基準で担保 | 感度を振って確認 |
| **判定基準の低速側の死角** | 「レンジ変化率と Doppler が1ビン以内で一致」は**低速では自動的に通ってしまう**。樹木クラッタ（レンジ変化率 ≈0、Doppler ±0.6）が 173532 で「実在の移動目標」と判定された。速い目標には有効だが、遅い目標と植生を区別できない | 最小速度の下限を設ける／複数フレームでの方向の一貫性を要求する |
| **ヘッダ 0x64〜0xB3** | 未同定。`Remove Static Clutter` の状態が入っている可能性 | 設定を振って `.dat` を差分比較 |
| **`Remove Static Clutter` が `.dat` に効くか** | 効くなら生サンプルが加工済みになる。現状は効かない前提 | 同じ場面を ON/OFF で 2 本録る |

要約すると、**軸のスケールと検出の事実は固く、絶対量（距離のオフセット・dB・角度の符号）が弱い。**
